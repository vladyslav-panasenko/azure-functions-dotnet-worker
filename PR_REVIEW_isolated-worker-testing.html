Scope and fidelity boundaries

Decide whether this is the right product capability before reviewing its implementation.

Medium risk
The gapThere is no official WebApplicationFactory-like facility for exercising an isolated worker application through its real entry point and worker pipeline.
The changeAdd a core in-process worker factory plus ASP.NET Core, Service Bus, and Blob testing companions.
The boundaryThis does not emulate the Functions host. It cannot prove listener, authorization, settlement, retry-scheduling, scale, or production-infrastructure behavior.

Application identity without global mutation

Make the worker load the test application’s assembly and directory while preserving parallel-test isolation.

High risk
WhyThe normal worker discovers its application from the process entry assembly and environment. A test host runs inside a different test process.
HowExecution-context-local assembly and directory contexts override discovery only inside the factory’s async flow, with existing behavior as fallback.
Main dangerA process-global environment or AppContext override would leak between factories and make parallel tests nondeterministic.

In-memory worker protocol

Drive the real worker message processor without opening a network listener or embedding the Functions host.

High risk
WhyCalling function methods directly bypasses metadata discovery, middleware, converters, FunctionContext, output binding, and protocol projection.
HowA channel-backed IWorkerClientFactory feeds protocol messages into the production IMessageProcessor and captures worker responses.
LifecycleStart stream → worker init → metadata discovery → exact function load → invocation/cancellation → termination.

Service Bus and Blob trigger testing

Verify SDK-shaped trigger payloads through the production worker path without claiming Functions-host behavior.

High risk
Service BusReconstructs real ServiceBusReceivedMessage values, batches, bodies, and standard binding metadata from protocol-neutral test values.
BlobSupports content and path-token assertions plus network-free creation of Blob SDK clients through the production Blob converter.
BoundaryNo listener starts. Completion, dead-lettering, lock renewal, Blob receipts, poison handling, retries, concurrency, and scale remain full-host tests.
Runnable examples and assertions 
ServiceBusReceivedMessage message = ServiceBusModelFactory.ServiceBusReceivedMessage(
    body: BinaryData.FromString("order-created"),
    messageId: "message-42",
    deliveryCount: 2,
    lockTokenGuid: Guid.NewGuid());

FunctionInvocationResult serviceBus = await factory.InvokeServiceBusAsync(
    "ServiceBusMessage", "message", message);
serviceBus.EnsureSucceeded();

FunctionInvocationResult blob = await factory.InvokeBlobAsync(
    "BlobBytes", "blob", BinaryData.FromString("invoice-content"),
    "invoices/42.txt",
    new Uri("https://account.blob.core.windows.net/testing/invoices/42.txt"));
blob.EnsureSucceeded();
